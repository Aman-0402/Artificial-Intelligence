Machine Learning Fundamentals

Bias is error from wrong assumptions — a high-bias model underfits (too simple, misses patterns). Variance is error from sensitivity to training data fluctuations — high-variance model overfits (memorises noise).

Tradeoff: decreasing bias (more complex model) increases variance, and vice versa. Goal: find the sweet spot that minimises total error = Bias² + Variance + Irreducible noise.

  • High bias → increase model complexity, add features
  • High variance → regularise, get more data, reduce features

Regularisation adds a penalty term to the loss function to discourage large weights, reducing overfitting.

  • L1 (Lasso): Penalty = λ·Σ|wᵢ|. Produces sparse weights (feature selection). Some weights → 0.
  • L2 (Ridge): Penalty = λ·Σwᵢ². Shrinks all weights proportionally. Rarely drives them to 0.
  • Elastic Net: Combines L1 + L2.

λ controls regularisation strength. Too large → underfitting.

Cross-validation evaluates model generalisation by training/testing on multiple data splits. k-fold CV: split data into k equal folds; train on k−1 folds, test on remaining fold; repeat k times; average scores.

Benefits: uses all data for both training and validation, reduces variance of performance estimate. Common: k=5 or k=10. Stratified k-fold preserves class ratios per fold.

Precision = TP / (TP + FP) — of predicted positives, how many are correct. Recall = TP / (TP + FN) — of actual positives, how many were found.

  • Prioritise precision when false positives are costly — e.g. spam filter (don't want legitimate email deleted), fraud alert sent to customer
  • Prioritise recall when false negatives are costly — e.g. cancer screening (must not miss cases), fraud detection (missing fraud is worse than false alarm)

F1 Score = harmonic mean of both. Use when both matter equally.

Random Forest is an ensemble of decision trees trained with: (1) Bootstrap sampling — each tree trains on a random sample with replacement (bagging). (2) Feature randomness — each split considers only a random subset of features.

Result: trees are decorrelated → variance reduces → better generalisation. Single tree: low bias, high variance. Random Forest: low bias, lower variance. Trade-off: less interpretable, slower.

Bagging (Random Forest): trains trees in parallel on random data subsets, averages predictions. Reduces variance.

Boosting (Gradient Boosting, XGBoost): trains trees sequentially. Each tree learns residual errors of the previous ensemble. Learning rate scales contribution. Reduces bias more aggressively.

Gradient Boosting fits each tree to the negative gradient of the loss function (pseudo-residuals). XGBoost adds regularisation, second-order gradients, and column/row subsampling for speed.

  • Resampling: Oversample minority class (SMOTE generates synthetic samples) or undersample majority class
  • Class weights: Set class_weight='balanced' in sklearn — penalises misclassifying minority class more
  • Threshold tuning: Lower decision threshold to increase recall for minority class
  • Metrics: Use F1, AUC-ROC, PR-AUC instead of accuracy
  • Ensemble methods: BalancedBaggingClassifier, EasyEnsemble

As feature count increases, data becomes increasingly sparse in high-dimensional space. Distance metrics lose meaning (all points become equidistant). Exponentially more data needed to sample space uniformly.

Effects: KNN performance degrades, overfitting increases. Mitigations: PCA/dimensionality reduction, feature selection, regularisation, more data.

Deep Learning

Backprop computes gradients of loss w.r.t. each weight by applying the chain rule backwards through the network: ∂L/∂w = ∂L/∂y · ∂y/∂z · ∂z/∂w (each factor is a local gradient).

Forward pass: compute predictions and cache activations. Backward pass: starting from loss, propagate gradient layer-by-layer. Weights updated via: w ← w − η·∂L/∂w. Requires differentiable activations.

BatchNorm normalises layer inputs to zero mean, unit variance per mini-batch, then scales/shifts with learnable γ and β. Applied before or after activation.

Benefits: (1) reduces internal covariate shift — activations stay in good range, (2) allows higher learning rates, (3) acts as mild regulariser (adds noise via batch statistics), (4) reduces sensitivity to weight initialisation.

Dropout randomly zeroes a fraction p of neuron activations during training. Each forward pass uses a different random subnetwork, forcing neurons to not co-adapt.

At inference: all neurons active, outputs scaled by (1−p). Approximates ensemble of 2ⁿ subnetworks. Common: p=0.5 for FC layers, p=0.1-0.3 for convolutional layers.

Vanishing: gradients shrink exponentially in early layers (sigmoid/tanh saturate). Learning stops for early layers.

Exploding: gradients grow exponentially, causing unstable updates (NaN loss).

Solutions: ReLU (avoids saturation), Gradient clipping (cap norm to threshold), Weight initialisation (He/Xavier), Batch Normalisation, Residual connections (skip connections provide gradient highway), LSTM gates (for RNNs).

Transfer learning uses a model pre-trained on large data (e.g. ImageNet, Common Crawl) as a starting point for a new task. Strategies:

  • Feature extraction: Freeze pretrained weights, train only new head
  • Fine-tuning: Unfreeze some/all layers, train at low learning rate

Use when: limited labelled data, similar domains. Dramatically reduces training time and data requirements. Examples: ResNet for medical imaging, BERT for sentiment analysis.

CNN: Captures local patterns via kernels. Parallelisable, fast. Good for: fixed-context local features, audio (1D conv), short sequences. Lacks inherent long-range dependencies without large receptive field.

RNN/LSTM: Maintains hidden state across timesteps. Handles variable-length sequences. Good for: time series, language modelling. Sequential = slower. LSTMs mitigate vanishing gradients for longer sequences.

In practice: Transformers outperform both for most NLP tasks. RNNs still used for streaming/real-time sequence tasks.

NLP & Transformers

Each token generates three vectors via learned projections: Query (Q), Key (K), Value (V). Attention score for token i attending to token j: score = QᵢKⱼᵀ / √dₖ. Softmax normalises scores → attention weights. Output = weighted sum of Values.

Multi-head attention runs h parallel attention heads with different projections, concatenates outputs. Allows model to attend to different representation subspaces simultaneously. Complexity: O(n²·d) — quadratic in sequence length.

  • BERT: Encoder-only. Bidirectional attention (sees full context). Trained with Masked LM + NSP. Best for: classification, NER, QA (understanding tasks)
  • GPT: Decoder-only. Causal (autoregressive) — each token attends only to previous tokens. Trained with next-token prediction. Best for: text generation, completion

T5 and BART use encoder-decoder (seq2seq). GPT-4 and Claude are decoder-only. BERT family (RoBERTa, DeBERTa) used for embeddings and classification.

Tokenisation splits text into model-processable units. BPE (Byte Pair Encoding) starts with characters, iteratively merges the most frequent adjacent pair into a new subword token. Result: common words → single token; rare words → subword pieces.

Benefits: handles out-of-vocabulary words, balances vocabulary size vs sequence length, language-agnostic. GPT uses BPE; BERT uses WordPiece (similar). Typical vocab: 30k–50k tokens.

RLHF (Reinforcement Learning from Human Feedback) has 3 phases:

  • SFT: Fine-tune base LLM on curated demonstration data (supervised)
  • Reward Model: Train a reward model on human preference pairs (rank completions A vs B)
  • PPO: Use RL (Proximal Policy Optimisation) to maximise reward model score while constraining KL-divergence from SFT model (prevents reward hacking)

Result: model outputs align with human preferences — more helpful, honest, harmless. Used in ChatGPT, Claude, Gemini.

RAG combines a retrieval system with LLM generation. At query time: (1) encode query → dense vector, (2) retrieve top-k similar documents from vector DB (FAISS, Pinecone), (3) prepend retrieved context to prompt, (4) LLM generates grounded response.

Benefits: up-to-date knowledge without retraining, reduces hallucinations, source attribution. Limitations: retrieval quality cap on response quality, context window limits amount of retrieved text.

  • Zero-shot: Direct instruction, no examples — "Classify this as positive/negative: ..."
  • Few-shot: Provide examples in the prompt showing input→output patterns
  • Chain-of-Thought (CoT): "Think step by step" — elicits reasoning before answer, improves complex tasks significantly
  • System prompts: Set persona, constraints, output format
  • Role prompting: "You are an expert ML engineer…"
  • Self-consistency: Sample multiple CoT paths, take majority vote

Statistics & Probability

P(A|B) = P(B|A)·P(A) / P(B) — posterior = likelihood × prior / evidence.

ML application: Naive Bayes classifier for text classification. Assumes feature independence. P(spam|words) ∝ P(words|spam)·P(spam). Fast, works well with limited data. Also: Bayesian hyperparameter optimisation updates a prior belief about good hyperparameters after each trial.

p-value = probability of observing data as extreme as seen, assuming null hypothesis H₀ is true. If p < α (e.g. 0.05), reject H₀.

Limitations: (1) does NOT measure effect size or practical significance, (2) affected by sample size — large n → tiny p even for trivial effects, (3) doesn't give P(H₀ is true), (4) multiple comparisons inflate false positive rate (Bonferroni correction needed), (5) p=0.05 threshold is arbitrary.

CLT: sampling distribution of the mean of any i.i.d. random variable converges to a normal distribution as sample size n→∞, regardless of the underlying distribution (given finite variance).

ML relevance: justifies using z-tests/t-tests on sample means, underpins confidence intervals for model metrics (e.g. mean accuracy over test folds), explains why summing many independent noise sources gives Gaussian noise.

MLE (Maximum Likelihood): θ* = argmax P(data|θ). Find parameters that make observed data most probable. No prior. Equivalent to minimising cross-entropy loss.

MAP (Maximum A Posteriori): θ* = argmax P(data|θ)·P(θ). Adds prior belief P(θ). Equivalent to MLE + regularisation. L2 prior → Ridge regression. L1 prior → Lasso.

With large data, MAP → MLE (data dominates prior). With small data, prior matters more.

ML System Design

Problem framing: Binary classification (fraud/not fraud). Severe class imbalance (<1% fraud).

Features: Transaction amount, velocity (txns/hour), location delta, merchant category, user history, device fingerprint, time-of-day patterns.

Model: Gradient Boosting (XGBoost) for tabular data. Rule-based layer for obvious patterns. Neural network for complex feature interactions.

Imbalance: SMOTE + class weights + low decision threshold. Optimise for recall (minimise missed fraud), monitor precision to limit false alerts.

Serving: Real-time scoring (<100ms). Feature store for pre-computed user features. Model versioned, A/B tested. Concept drift monitoring — fraud patterns evolve.

Data drift: input feature distribution shifts over time (covariate shift). Concept drift: relationship between features and target changes (P(y|X) changes).

Monitoring approaches:

  • Statistical tests: KS test, PSI (Population Stability Index), chi-squared for categorical features
  • Model performance tracking: monitor accuracy/AUC on labelled samples over time
  • Output distribution: monitor prediction score distribution shifts
  • Feature importance drift: check if important features change

Response: retrain on recent data, trigger alerts when drift exceeds threshold.

  • Quantisation: Convert FP32 weights → INT8 (4x smaller, faster). Slight accuracy drop
  • Pruning: Remove near-zero weights. Reduce model size
  • Knowledge distillation: Train small "student" model to mimic large "teacher"
  • Batching: Process multiple requests together (GPU efficiency)
  • Caching: Cache embeddings for repeated inputs
  • ONNX export: Optimised inference runtime, hardware-specific kernels
  • TensorRT / CoreML: Hardware-specific compilation

Approaches:

  • Collaborative filtering: Based on user-item interaction matrix. Matrix factorisation (SVD, ALS). "Users like you also liked…"
  • Content-based: Item feature similarity. Recommend similar items to what user interacted with
  • Two-tower neural: Separate encoders for user/item, score = dot product of embeddings (YouTube, TikTok approach)

Pipeline: Candidate generation (recall, millions→hundreds) → Ranking (precision, hundreds→top-k) → Business rules (diversity, freshness).

Cold start: New users → popular items or ask preferences. New items → content-based until interactions accumulate.

A/B test: randomly assign users to control (old model) and treatment (new model), measure metric difference with statistical significance.

Pitfalls:

  • Peeking: Stopping early when significant — inflates false positive rate. Fix: pre-specify sample size
  • Multiple metrics: Bonferroni correction needed. Choose one primary metric
  • Network effects: Users interact — treatment leaks to control (social platforms)
  • Simpson's paradox: Aggregate results reverse when stratified by subgroup
  • Novelty effect: Users engage with new things initially — wait for stabilisation

Batch learning: Train on full dataset, deploy fixed model. Retrain periodically. Simple, stable. Fails when data distribution changes rapidly.

Online learning: Update model incrementally with each new sample or mini-batch. Adapts to drift continuously. Algorithms: SGD, Vowpal Wabbit, River (Python). Risk: noisy updates, catastrophic forgetting.

Hybrid: mini-batch retraining on sliding window (e.g. retrain daily on last 30 days of data).
