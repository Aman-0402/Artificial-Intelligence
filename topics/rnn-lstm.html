Recurrent Neural Networks & LSTMs

⏱ 12 min read

Standard feedforward neural networks process each input independently — they have no memory of what came before. But language, audio, time series, and video are all sequential: the meaning of a word depends on the words before it; tomorrow's stock price depends on yesterday's. Recurrent Neural Networks (RNNs) are designed specifically for this kind of data, maintaining a hidden state that carries information from step to step.

🔁
The Key Idea
At each time step t, an RNN receives the current input xₜ and the previous hidden state hₜ₋₁, then produces a new hidden state hₜ = f(W·xₜ + U·hₜ₋₁ + b). The hidden state acts as a compressed memory of everything seen so far.

Use Cases for Sequential Models

  • Natural Language Processing — sentiment analysis, named entity recognition, machine translation
  • Speech Recognition — converting audio waveforms (sequences of amplitudes) to text
  • Time Series Forecasting — stock prices, weather, energy demand, sensor readings
  • Music Generation — predicting the next note given a sequence of previous notes
  • Video Analysis — understanding temporal dynamics across frames

The Vanishing Gradient Problem in RNNs

Vanilla RNNs struggle with long-range dependencies — connections between elements far apart in a sequence. During backpropagation through time (BPTT), gradients must flow backwards through every time step. Because the same weight matrix is applied repeatedly, gradients are multiplied by that matrix over and over. With many time steps, small values shrink exponentially to zero (vanishing) or large values explode (exploding).

⚠️
Consequence
A vanilla RNN reading "The cat that sat on the mat was..." forgets "cat" by the time it needs to predict "was hungry." It simply cannot retain information over 20+ steps. This is the fundamental limitation that LSTMs were invented to solve.

Long Short-Term Memory (LSTM)

Proposed by Hochreiter & Schmidhuber in 1997, the LSTM solves the vanishing gradient problem with a carefully designed architecture that maintains two separate states:

  • Cell State (Cₜ) — the long-term memory. A highway running through the entire sequence with only minor linear interactions, so gradients can flow back many steps without vanishing.
  • Hidden State (hₜ) — the short-term working memory passed to the next step and used for output.

Three learned gates control what information is stored, discarded, or output at each step:

The Three LSTM Gates

1. Forget Gate

Decides what to erase from the cell state. Outputs a value between 0 (forget everything) and 1 (keep everything) for each element of the cell state:

fₜ = σ(Wf · [hₜ₋₁, xₜ] + bf)

Example: when processing a new subject in a sentence, the forget gate discards the previous subject's gender information from memory.

2. Input Gate

Decides what new information to write into the cell state. Two sub-components: the input gate selects which values to update, and a tanh layer creates candidate values:

iₜ = σ(Wi · [hₜ₋₁, xₜ] + bi)
C̃ₜ = tanh(Wc · [hₜ₋₁, xₜ] + bc)
Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ C̃ₜ

3. Output Gate

Decides what part of the cell state to expose as the hidden state (output) for this time step:

oₜ = σ(Wo · [hₜ₋₁, xₜ] + bo)
hₜ = oₜ ⊙ tanh(Cₜ)

💡
Intuition Summary
Forget gate: "What old info is no longer relevant?"
Input gate: "What new info should I store?"
Output gate: "What should I reveal to the next step?"

The cell state is the long-term memory notebook. Gates selectively read, write, and erase — like a smart clipboard that knows what to keep.

GRU — Gated Recurrent Unit

The GRU (Cho et al., 2014) is a simplified alternative to the LSTM. It merges the cell state and hidden state into one, and replaces the three LSTM gates with just two:

  • Reset Gate — controls how much of the past hidden state to forget when computing the new candidate state
  • Update Gate — controls how much of the previous hidden state to carry forward vs how much to replace with new content (combines the LSTM's forget and input gates)

With fewer parameters, GRUs train faster and often match LSTM performance on many tasks — especially with limited data. They are a strong default choice when you need a recurrent model but want lower compute cost.

Property Vanilla RNN LSTM GRU
States 1 (hidden) 2 (cell + hidden) 1 (hidden)
Gates None 3 (forget, input, output) 2 (reset, update)
Long-range memory Poor Excellent Good
Parameters Fewest Most Fewer than LSTM
Training speed Fastest Slowest Faster than LSTM

LSTM Code Example

Below is a complete example using an LSTM for sentiment classification on the IMDB movie review dataset (binary: positive/negative):

import tensorflow as tf
from tensorflow import keras

# IMDB: 25,000 training reviews, 25,000 test reviews
# Vocabulary limited to top 10,000 words; pad/truncate to 200 tokens
MAX_FEATURES = 10_000
MAX_LEN      = 200
EMBED_DIM    = 64

(x_train, y_train), (x_test, y_test) = keras.datasets.imdb.load_data(
    num_words=MAX_FEATURES
)

x_train = keras.preprocessing.sequence.pad_sequences(x_train, maxlen=MAX_LEN)
x_test  = keras.preprocessing.sequence.pad_sequences(x_test,  maxlen=MAX_LEN)

# Build LSTM model
model = keras.Sequential([
    keras.layers.Embedding(MAX_FEATURES, EMBED_DIM, input_length=MAX_LEN),
    keras.layers.LSTM(128, return_sequences=True, dropout=0.2),
    keras.layers.LSTM(64,  dropout=0.2),
    keras.layers.Dense(32, activation="relu"),
    keras.layers.Dense(1,  activation="sigmoid")   # binary classification
])

model.compile(
    optimizer="adam",
    loss="binary_crossentropy",
    metrics=["accuracy"]
)

model.summary()

history = model.fit(
    x_train, y_train,
    epochs=5,
    batch_size=128,
    validation_split=0.1
)

test_loss, test_acc = model.evaluate(x_test, y_test, verbose=0)
print(f"Test accuracy: {test_acc:.4f}")   # ~0.87

LSTM vs Transformer — When to Use Which

Since the Transformer (2017) and its descendants (BERT, GPT, T5) dominated NLP benchmarks, the question arises: when should you still use an LSTM?

Scenario Prefer LSTM/GRU Prefer Transformer
Dataset size Small to medium (<100K samples) Large (millions of samples)
Sequence length Moderate (up to ~500 tokens) Very long or variable length
Compute budget Low (runs well on CPU) High (typically needs GPU/TPU)
Real-time streaming Yes (processes one step at a time) Harder (attention needs full context)
Time series / IoT Natural fit Temporal Fusion Transformer (specialised)
NLP state-of-the-art No longer competitive Yes — BERT, GPT-4, etc.
💡
Practical Recommendation
For most NLP tasks with ample data, use a pretrained Transformer (e.g., DistilBERT via Hugging Face) with transfer learning. For time series, sensor data, embedded systems, or real-time inference with limited compute, LSTMs and GRUs remain the practical, well-understood, production-proven choice.
